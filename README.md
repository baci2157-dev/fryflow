# FryFlow 🍟

**CRM оптовых продаж замороженного картофеля фри** — рабочее место продавца, который живёт в машине и на телефоне: клиенты, звонки, заказы, склад, долги, регионы, Telegram-заявки и ИИ-Директор.

- Товар: картофель фри 2,5 кг — **300 ₽/уп (120 ₽/кг) от 10 коробок**, мелкий опт 350 ₽
- Клиенты: шаурмичные, бургерные, пабы, столовые (green / yellow / red), есть сети
- Склад: 3 400 кг (1 360 уп.), движение списывается заказами автоматически
- Ставьте на телефон как приложение (PWA) — работает в подвале без сети

---

## Что внутри

| Раздел | Что делает |
| --- | --- |
| **Дашборд** | KPI дня, план задач, совет ИИ, индикатор сети |
| **Клиенты** | База с приоритетами, Health Score, заметки, журнал звонков |
| **Звонки** | Воронка холодных продаж + скрипты + калькулятор выгоды |
| **Карта / Маршрут** | Точки клиентов на карте, маршрут дня по вместимости машины |
| **Заказы** | Сделки полного цикла, вкладка «Черновики» — заявки из Telegram |
| **Склад** | Остаток = сумма движений, порог «пора заказывать» |
| **Финансы / Долги** | Выручка, маржа, дебиторка с возрастом долга, PDF-счёт |
| **Регионы** | Оптовики Краснодара, Волгограда, Ставрополя (Первый контакт → Тест → Фура) |
| **ИИ-Директор** | Чат с ИИ на живых цифрах бизнеса + проактивные советы |
| **Маркетинг** | Календарь автопостинга в группы Telegram |
| **Настройки** | Реквизиты PDF-счёта, устав ИИ, Telegram, резервные копии |

Технологии: Next.js 16 (App Router), TypeScript, Tailwind CSS 4, Zustand, framer-motion. Работает на **моках** (localStorage) из коробки — и готова к **Supabase** (см. ниже).

## Быстрый старт (локально)

Нужен [Bun](https://bun.sh) (или Node 20+):

```bash
bun install        # установить зависимости
bun run dev        # http://localhost:3000
```

Приложение сразу работает на демо-данных — ничего настраивать не нужно.

Продакшн-сборка: `bun run build && bun run start`.

## Установка на телефон (PWA)

Приложение устанавливается как нативное: своя иконка (золотая картошка), полный экран, работает офлайн.

> Для установки нужен **HTTPS**: локальный `localhost` или деплой на Vercel (см. ниже).

**iPhone (Safari):**
1. Откройте адрес приложения в Safari.
2. Кнопка «Поделиться» (квадрат со стрелкой вверх).
3. «На экран „Домой“» → Добавить.
4. Иконка FryFlow на рабочем столе — открывается без Safari.

**Android (Chrome):**
1. Откройте адрес приложения в Chrome.
2. Меню ⋮ → «Установить приложение» / «Добавить на главный экран».

**Проверка офлайна:** включите авиарежим и откройте FryFlow — интерфейс откроется из кэша (Service Worker), заказы и заметки работают (localStorage), индикатор сети на Дашборде красный. Серверные действия (пост в группу, тест Telegram) копятся в очередь — на Дашборде появится баннер «Ожидает синхронизации», и всё уйдёт само при появлении сети. Тот же эффект в браузере: DevTools → Network → Offline.

## Подключение Supabase (реальная база)

По умолчанию FryFlow работает на моках (localStorage) — демо-режим. Supabase станет единым источником правды:

1. **Создайте проект**: [supabase.com](https://supabase.com) → New project (регион EU Central поближе к югу России). Бесплатного тарифа хватает.
2. **Создайте таблицы**: в проекте откройте **SQL Editor** → New query → вставьте содержимое файла [`supabase/schema.sql`](supabase/schema.sql) целиком → **Run**. Появятся 8 таблиц: `clients`, `calls`, `orders`, `inventory_movements`, `payments`, `regional_partners`, `settings`, `order_drafts` — с индексами и защитой (RLS).
3. **Возьмите ключи**: **Project Settings → API** → скопируйте `Project URL` и `anon public` ключ.
4. **Создайте `.env.local`** в корне проекта:

   ```
   NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
   ```

5. **Перезапустите** `bun run dev`. Готово: сервисный слой (`src/lib/queries.ts`) увидит ключи и начнёт писать в базу; без ключей — работает на моках. Записи при отсутствии сети встанут в IndexedDB-очередь и синхронизируются сами.

> **Доступ к данным.** Таблицы закрыты политиками RLS — читать и писать может только аутентифицированный пользователь. Чтобы включить вход: Supabase → Authentication → Providers → Email (или magic link). Аноним с публичным ключом не видит ничего.

## Деплой на Vercel

1. Запушьте репозиторий в GitHub.
2. [vercel.com](https://vercel.com) → Add New → Project → импортируйте репозиторий.
3. Environment Variables (Server & Client):

   | Переменная | Зачем |
   | --- | --- |
   | `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | база (не обязательно) |
   | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Telegram-бот на сервере (см. ниже) |

4. Deploy. Через минуту — HTTPS-адрес, ставьте PWA на телефон с него.

## Telegram-бот (заявки клиентов и автопостинг)

1. **Создайте бота**: напишите [@BotFather](https://t.me/BotFather) → `/newbot` → имя и username → получите токен вида `7123456789:AAHf…`.
2. **Узнайте Chat ID**: напишите [@userinfobot](https://t.me/userinfobot) — он ответит вашим числом (Id).
3. **В приложении**: Настройки → Telegram → вставьте токен и Chat ID → нажмите Start у своего бота в Telegram → «Отправить тестовое сообщение».
4. **Заявки клиентов (Business Mode)**: @BotFather → `/mybots` → ваш бот → Settings → Business Mode → подключите личный аккаунт. Клиенты пишут вам в личку, ИИ разбирает сообщение («нужно 15 коробок на четверг» → 15 уп., ближайший четверг) и кладёт заявку во вкладку «Черновики» в «Заказах».
5. **Вебхук** (чтобы бот получал сообщения) — одна команда в браузере:

   ```
   https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://ваш-домен/api/telegram/webhook
   ```

6. **Автопостинг**: Настройки → Telegram → «Автопостинг в группы» — добавьте бота администратором в группы оптовиков, укажите их Chat ID и интервал (2/3/7 дней). ИИ каждый раз переписывает шаблон по-новому (анти-спам) и подставляет живые остатки склада. Календарь и кнопка «Опубликовать сейчас» — в разделе «Маркетинг».

**Безопасность**: токен хранится только на сервере (`.data/telegram.json` или `TELEGRAM_BOT_TOKEN` на Vercel; для self-hosted каталог переносится переменной `FRYFLOW_DATA_DIR`). Каталог `.data` и файл `.env` в `.gitignore` — токен не попадает в репозиторий. Клиентский код видит маску `12345…AbCd`, но не токен.

## Структура проекта

```
src/
  app/                 # экраны (App Router): дашборд, клиенты, заказы… + api/
    api/telegram/      # серверные роуты: webhook, autopost, config, test, drafts
  components/          # UI: layout (каркас), dashboard, crm, orders, pwa, offline
  lib/
    queries.ts         # сервисный слой: каждая функция if (supabase) … else мок
    supabase.ts        # клиент Supabase (null → мок-режим)
    offline-queue.ts   # офлайн-очередь на IndexedDB + автосинхронизация
    clients-store.ts   # сторы Zustand (localStorage): CRM, заказы, регионы…
    ai-triggers.ts     # проактивный ИИ: интервалы, критичность, Telegram
    telegram-server.ts # серверная интеграция Telegram (токен только здесь)
    pdf-invoice.ts     # PDF-счёт с реквизитами
    backup.ts          # резервная копия (JSON) всех данных
  types/models.ts      # модели данных и бизнес-константы
public/
  manifest.json        # PWA-манифест
  sw.js                # Service Worker (stale-while-revalidate для GET)
  icons/               # иконки 192/512 + maskable + apple-touch
supabase/schema.sql    # 8 таблиц + RLS + индексы
```

## Резервные копии

Настройки → «Данные и резервное копирование» → **«Скачать резервную копию (JSON)»** — выгружает всё из текущего режима (моки или Supabase): клиентов, звонки, заказы, склад, оплаты, регионы, настройки. Там же — сброс демо-данных с подтверждением (два нажатия).
